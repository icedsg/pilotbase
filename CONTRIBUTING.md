# Contributing

Thanks for your interest in improving Pilotbase.

## Before you open a pull request

This project is source-available under the [Pilotbase Limited Use
License](LICENSE), not a traditional open source license — see the
LICENSE file for what that means for using and modifying the code.

Contributions are handled separately from that license. Anything you
submit (code, docs, tests, etc.) is governed by our
[Contributor License Agreement](CLA.md), which briefly means:

- You keep copyright in what you write.
- You grant the project owner an exclusive license to use, modify, and
  relicense your contribution (including commercially).
- You confirm the contribution is your own work and doesn't infringe
  anyone else's rights.

Read [CLA.md](CLA.md) for the full terms.

## How signing works

The first time you open a pull request, a CLA Assistant bot will comment
with a link to the CLA and ask you to reply with the agreement text it
provides. Signing is a one-time step — it's remembered for any future
pull requests you open. Until you sign, the PR's CLA check will stay
pending.

## Review

All pull requests require review and approval from the project owner
before merging, regardless of who opens them. There's no fixed SLA for
review — for small fixes, feel free to open the PR directly; for larger
changes, consider opening an issue first to discuss the approach before
investing significant time.

## Getting started

1. Fork the repo and create a branch off `master`.
2. Make your change.
3. Open a pull request describing what changed and why.
4. Sign the CLA when the bot prompts you (see above).
